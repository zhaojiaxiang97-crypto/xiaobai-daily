# i18n 假设被证伪：注册插件后 `$setup` 仍 60 个

> round-0476
>
> 上轮推断 `$setup.i` 是「测试环境缺 i18n 插件」。这轮实测**证伪**。

## 实验

建了两个测试工程，都注册 `vue-i18n` 插件（`createI18n({legacy:false, locale:'en-US',
messages:{'en-US':{}}})` + `app.use(i18n)`）：

| 版本 | 说明 |
|---|---|
| 基线 | 当前 `gen-main.cjs`（无 setup 内联） |
| 实验 | `3137b3c` 的 gen-main + 四条修法（多 declarator 拆分 / props 无条件绑定 / inlineText 扫描 / 排除赋值） |

## 结果

| 版本 | OK | EMPTY | ERR | slots | `$setup` |
|---|---|---|---|---|---|
| **基线 + i18n** | **98** | 52 | 242 | 59 | 11 |
| **实验 + i18n** | **44** | 19 | 329 | **0** | **60** |
| 基线（无 i18n，历史） | 98 | 52 | 242 | 59 | 11 |
| 实验（无 i18n，历史） | 42 | 18 | 332 | 0 | 61 |

**i18n 插件对两边都没有实质影响**：
- 基线：98 → 98（无变化）
- 实验：42 → 44（+2，噪声范围）
- `$setup` 错误：61 → 60（没有改善）

## 结论

**假设证伪。** `$setup.i is not a function` 不是 i18n 插件缺失导致的。

`S_it` 虽然指向 `vue-i18n.runtime.js` 的 `n` 导出，但注册标准 i18n 插件后
`it()` 的返回值里仍然没有 `t` 字段 —— 说明：

1. `n` **不是** `useI18n`（是 runtime 里的别的东西）
2. 或者原应用用的不是标准 `vue-i18n` 的用法（自定义包装）

**setup 内联版本 OK 44 < 基线 98，且原因不是环境，而是内联引入的新错误。**
