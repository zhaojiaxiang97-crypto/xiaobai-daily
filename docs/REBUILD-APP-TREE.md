# 还原「组件在应用里的样子」：路径验证 + 两个实质阻碍

> round-0502
>
> 目标：给每个组件配真实 props 和父组件，还原它在应用里的样子。
> 这轮验证了技术路径，但也撞到了两个绕不过去的阻碍。

## 做了什么

### 1. 从运行的应用 dump 完整组件树

遍历 Vue 的 `instance.subTree`，提取每个节点的**组件名 + props + 父子关系**：

| 页面 | 组件实例数 |
|---|---|
| 今日工作 | 232 |
| 待办 | **1394** |
| 生成报告 | 570 |
| 记忆时间线 | 500 |
| 热力图 | 364 |
| 应用记录 | 197 |
| 历史报告 | 370 |
| API 设置 | 186 |
| 隐私保护 | 256 |

**总计 4069 个真实组件实例**，含 props 和结构。

### 2. 检查组件名能否对应到生成的 .vue

110 个不同的组件名，**108 个有真名**（只有 `(anon)` 和 `c` 是压缩名）。

| 项 | 数量 |
|---|---|
| 有真名的组件 | 108 |
| **在 `vue/` 里存在的** | **88（81%）** |
| 缺失 | 20（`DialogRoot`、`Primitive`、`Presence`、`BaseTransition` 等） |

**出现最多的**：`Presence`(369)、`DialogContent`(289)、`DialogOverlay`(289)、
`Primitive`(225)、`Teleport`(209)、`DialogRoot`(169)、`Button`(57)。

**这些和生成的 `.vue` 文件名一致** —— 所以能 import。

### 3. 写重建页并跑通

用树结构递归 `h(组件, props, children)`，强制 `open: true`。

**结果**：状态 `OK:578`，页面确实渲染出了 HTML 结构。**技术路径是通的。**

## 两个实质阻碍

### 阻碍 1：树里大量匿名节点

232 个节点里，**只有 113 个名字能对应到 `.vue`**，其余是 `(anon)` 和 `c`
（压缩后的组件定义，拿不到名字）。

**所以重建出来的树有大半是占位 div**：

```html
<div class="ph-wrap"><div class="ph-wrap"><!----><div class="ph-wrap">...
```

### 阻碍 2：组件本身有反编译遗留错误

渲染时 13 个错误：

| 错误 | 数量 |
|---|---|
| `Cannot read properties of null (reading 'ce')` | 11 |
| `u is not defined` | 1 |
| `Cannot read properties of undefined` | 1 |

**这些不是重建逻辑的问题** —— 是组件本身在特定上下文里的老问题
（`ce` 是 reka-ui 内部 context，`u is not defined` 是符号补位遗留）。

## 结论

| 项 | 状态 |
|---|---|
| dump 真实组件树 | ✅ 4069 个实例 |
| 组件名 → .vue 映射 | ✅ 81%（88/108） |
| 重建渲染页 | ✅ 跑通（OK:578） |
| **还原出可辨认的画面** | ❌ **树大半是匿名占位** |
| **组件无错渲染** | ❌ **有 13 个遗留错误** |

**路径是对的，但要真正「还原应用里的样子」，得先解决这两件事**：

1. **扩展组件映射表**，让 `(anon)` / `c` 也能对应到 `.vue`
   （需要 deep-dive 到每个匿名 vnode 的 `type` 结构）
2. **修掉组件的遗留错误**（`ce`、`u is not defined`）
   —— 但这些是前面十几轮反复撞到的同一个问题，没有低成本解法

## 判断

**这是一个「路径清楚但成本远高于预期」的任务。** 不是技术不可行，
是需要先补两个前置工程，而那两个前置工程各自都比这一轮大。

**已交付的部分**：4069 个实例的真实组件树数据（可复用），
以及验证了「按树重建」的技术可行性。
